# South African language identification

A reproducible CPU experiment that classifies text into the eleven languages in the ExploreAI Academy 2023 hackathon dataset. It compares a word TF-IDF / Naive Bayes baseline with a character TF-IDF / linear SVM, then evaluates one frozen choice on a reserved local holdout.

This project connects data preparation, feature engineering, model evaluation and reusable inference. It is coursework/hackathon work with a 2026 Codex-assisted engineering extension. It is a local experiment, not a deployed service or an official Kaggle result.

## What changed

The historical SVM notebook refers to an undefined vectorizer at inference and subsequently uses validation predictions in test-output construction. The new code fits, saves and predicts with one complete scikit-learn pipeline. It also replaces aggressive language-related cleaning with label-independent Unicode normalization, prevents identical normalized texts crossing splits, reports each language separately, and preserves failed attempts rather than silently overwriting them.

Original notebooks and history are retained. Their saved outputs are historical, not fresh verified results. Read [the original README](docs/LEGACY_README.md) for the original hackathon introduction.

## Reproduce on Windows

Use Python 3.12 in a project-local environment. The five runtime dependencies are pinned; training uses CPU and one numerical-library thread. No model download, tracker key, external API, cloud account or paid service is needed. Data must be obtained through an authorized source; no automatic dataset downloader is included.

```powershell
py -3.12 -m venv .venv
& .venv/Scripts/python.exe -m pip install --only-binary=:all: -r requirements.txt
& .venv/Scripts/python.exe -m unittest discover -s tests -v

# Use the original labelled training CSV, not the competition test CSV.
& .venv/Scripts/python.exe -m sa_lid prepare --data data/train_set.csv --run .local/portfolio-v1
& .venv/Scripts/python.exe -m sa_lid select --run .local/portfolio-v1
& .venv/Scripts/python.exe -m sa_lid evaluate --run .local/portfolio-v1
& .venv/Scripts/python.exe -m sa_lid predict --run .local/portfolio-v1 --text "This example sentence is written in English."
```

On Linux/macOS, create the environment with python3.12 -m venv .venv and replace .venv/Scripts/python.exe with .venv/bin/python.

The prepare command refuses an existing run directory. Selection is allowed once, and evaluation marks the holdout consumed before predicting. Save failures and investigate them; do not start another run to tune against the final result. The saved pipeline remains fitted only on the training partition. Inference checks its source, environment, protocol and artifact checksums. Load only models generated by your own trusted local run; joblib is not a sandbox for third-party files.

Outputs stay in .local/: frozen protocol, aggregate audit, validation results, selected pipeline, final report and per-language CSV. Local data, model binaries, prediction rows and split indices are excluded from the new publication candidate. Historical tracked files remain tracked; ignore rules do not remove them.

## What the checks establish

Tests cover Unicode handling, duplicate/conflicting-label handling, disjoint partitions, fitting vectorizers on training only, saved-pipeline inference, dataset/model/protocol integrity, and one-use holdout evaluation. Software tests do not measure predictive performance; the separately recorded experiment does.

The comparison uses newly defined validation and holdout partitions. It is not comparable to old notebook scores or a Kaggle leaderboard. Exact normalization groups do not eliminate near-duplicate documents or shared-source leakage. No document IDs or time split are available. This benchmark does not establish performance on short messages, code-switching, unknown languages or unseen domains. Per-language diagnostics do not prove fairness.
