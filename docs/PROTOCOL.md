# Evaluation protocol

Frozen before the first development run. This is a local portfolio experiment over the existing labelled training CSV. It does not use external text, pretrained models, the Kaggle test set, a leaderboard score, cloud compute or tracking services.

1. Require the original `lang_id,text` schema and all eleven benchmark language codes. Normalize with Unicode NFKC, case folding and whitespace collapse. Preserve diacritics, punctuation and short words. The historical cleaning removes short words and applies language-related processing; the new transform does not require the unknown label at prediction time.
2. Collapse identical normalized text with a consistent label to one representative. Exclude all rows in groups with conflicting labels, and report counts. This makes exact normalized-text groups disjoint across splits. Near duplicates, document-source overlap, dialect coverage and temporal shifts remain unmeasured.
3. Sort by normalized-text SHA-256 and stratify into 60% training, 20% validation and 20% holdout with seed 42. The source CSV hash, code hash, environment, candidate parameters, partition indices and counts are saved before model fitting. Label counts are used for stratification; holdout predictions/metrics are not used for selection. The existing 2023 work predates this split, so this is a newly reserved evaluation, not a claim that the source corpus was historically unseen.
4. Compare exactly two fixed pipelines: word TF-IDF plus Multinomial Naive Bayes (`alpha=1`), then character-within-word TF-IDF (3-5 grams, at most 150,000 features) plus LinearSVC (`C=1`, seed 42, at most 3,000 iterations). The first is a new baseline inspired by the old notebook, not a rerun of its old cleaning, split or score. Fit vectorizers on training rows only. One CPU thread; no parameter sweep or retry loop. Fail on nonconvergence.
5. Select by validation macro F1, with lexical candidate-name tie break. Save the entire fitted pipeline, frozen selection, checksums and validation diagnostics. Do not refit on validation. Selection cannot be repeated in that run directory, even after failure; preserve the failed receipt.
6. After selection is frozen, evaluate the chosen pipeline on the internal holdout once. An exclusive marker is created before predictions. Report accuracy, macro/weighted F1, precision/recall/F1/support per language, confusion counts, predeclared character-length slices and local runtime. Do not use the final result to tune another model in this portfolio experiment.
7. Prediction calls the saved pipeline on normalized text. It does not recreate a separate vectorizer or reuse predictions from validation. The eleven labels form a closed set; unknown languages, code-switching and confidence-based abstention are not supported. Never load legacy or downloaded pickle files. The CLI checksum is an integrity check for your own trusted local artifact, not a security sandbox for malicious joblib files.

The CLI guards accidental repeat use within a run, but cannot stop someone creating a new run or editing receipts. Honest experiment governance is still required. Per-language differences are evaluation diagnostics, not proof of fairness or deployment readiness.

References: [scikit-learn leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage), [text feature extraction](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction), [LinearSVC](https://scikit-learn.org/stable/modules/generated/sklearn.svm.LinearSVC.html), [macro F1](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html).
